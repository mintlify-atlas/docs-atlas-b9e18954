Configuration for Backtest Index Fund lives in two places: strategy-level constants and a `setConfig()` call at the top of `content/sep_2020/main.strategy.ts` control the fund's behaviour and the engine's simulation parameters, while Docker environment variables and the launcher config govern the persistence services the engine depends on.

## Strategy constants

These constants are declared at the top of `main.strategy.ts` in every month folder. The reference month is `content/sep_2020/main.strategy.ts`; all other months are stamped from it by the generator and share the same constant values — only the `BASKET` block and the exchange-module frame differ between months.

<ParamField body="DEPOSIT_USD" type="number" default="1000">
  The fixed total deposit in US dollars that the fund allocates each week. It is split equally across the basket symbols (each symbol gets `DEPOSIT_USD / BASKET.length`), and the remainder dictated by the gate is parked in `PARKING_SYMBOL`. Because backtest-kit has no shared portfolio balance, this constant sets the notional size of each independent per-symbol backtest.
</ParamField>

<ParamField body="PARKING_SYMBOL" type="string" default='"PAXGUSDT"'>
  The counter-position symbol that receives the fraction of the deposit kept out of the basket by the gate. When the gate is `0` (all six lookback windows vote bearish on BTC), the entire deposit goes to this symbol. When the gate is `1`, this leg returns `null` instead of a signal and sits out the week. Defaults to PAXG, the tokenized gold instrument on Binance.
</ParamField>

<ParamField body="HOLD_MINUTES" type="number" default="10079">
  The lifetime of every position in minutes, computed as `7 * 24 * 60 - 1`. Positions open long on the first hourly tick and close by `time_expired` at 23:59 seven days later. The one-minute shortfall ensures the closing tick lands at 23:59 and the re-entry tick lands at 00:00, avoiding an extra hour in the candle cache.
</ParamField>

<ParamField body="GATE_SYMBOL" type="string" default='"BTCUSDT"'>
  The reference asset used to compute the trend gate. Daily candles for this symbol are fetched with `getCandles` inside a `Cache.fn` wrapper that recomputes once per day and is automatically invalidated when the engine advances to the next day. No look-ahead is possible because `getCandles` is trimmed to the current backtest timestamp.
</ParamField>

<ParamField body="GATE_WINDOWS_DAYS" type="number[]" default="[20, 25, 30, 35, 40, 45]">
  The ensemble of lookback windows (in days) used to compute the gate. For each window `N`, the gate asks whether BTC's last close is higher than the close `N` days ago. The gate value is the fraction of windows that vote "yes" — a number between `0` and `1` in steps of `1/6`. Using an ensemble of six windows across a plateau rather than a single moving average makes the result insensitive to the exact choice of `N`.
</ParamField>

<ParamField body="STOP_LOSS_PERCENT" type="number" default="50">
  The stop-loss distance as a percentage below the entry price, passed to `Position.bracket`. This level is intentionally unreachable in one week on a spot position without leverage. The only normal exit path is `time_expired`; this constant exists solely to satisfy the engine's position validator.
</ParamField>

<ParamField body="TAKE_PROFIT_PERCENT" type="number" default="500">
  The take-profit distance as a percentage above the entry price, passed to `Position.bracket`. Like `STOP_LOSS_PERCENT`, this is a technical sentinel value — a 500 % gain in seven days on a spot asset is not expected. The `closeReason` in every closed row of the report should read `time_expired`.
</ParamField>

## Engine `setConfig` options

`setConfig` is called once, at the top of `main.strategy.ts`, immediately after the imports. It adjusts two engine defaults that must be changed for the daily-candle simulation to behave correctly.

```typescript
setConfig({
  CC_MAX_STOPLOSS_DISTANCE_PERCENT: 100, // allow the technical −50 % stop through the validator
  CC_BACKTEST_STEP_MINUTES: 24 * 60,     // evaluate positions once per day, not every minute
});
```

<ParamField body="CC_BACKTEST_STEP_MINUTES" type="number" default="1440">
  Sets the engine's position-evaluation cadence to `24 * 60` (1440 minutes = one full day). Because the Yahoo Finance adapter synthesizes minute candles by repeating a daily bar across all 1440 minutes of the day, evaluating positions every minute would produce 1440 identical decisions. Setting this to one day makes the engine skip ahead to the next daily bar in a single step, so a full month runs in seconds instead of minutes and a full 73-month history runs in a few minutes.
</ParamField>

<ParamField body="CC_MAX_STOPLOSS_DISTANCE_PERCENT" type="number" default="100">
  Raises the maximum stop-loss distance the engine's validator will accept to `100 %`. The default limit is lower than the `STOP_LOSS_PERCENT` value of `50 %` used in this strategy, which would cause the validator to reject every signal. Setting this to `100` allows the technical stop to pass validation while remaining effectively unreachable in practice.
</ParamField>

<Note>
  `setConfig` must be called **only** in `main.strategy.ts`. The exchange module (`modules/backtest.module.ts`) registers schemas and adapters; it must not call `setConfig` or alter any engine-level behaviour. This is a hard rule of the repository — mixing configuration into the exchange module would make months non-reproducible in isolation.
</Note>

## Redis environment variable

The Redis Docker container starts with password authentication enforced. You must supply the same password to the engine via a `.env` file in the project root before running any strategy.

<ParamField body="CC_REDIS_PASSWORD" type="string">
  The password the engine uses to authenticate with Redis. It must match the value set in `docker/redis/docker-compose.yaml`. Based on the default Compose file, the value is:

  ```bash
  # .env
  CC_REDIS_PASSWORD=mysecurepassword
  ```

  The Compose file passes this to the container both as an environment variable and as the `--requirepass` argument to `redis-server`:

  ```yaml
  environment:
    - REDIS_PASSWORD=mysecurepassword
  command: ["redis-server", "--requirepass", "mysecurepassword"]
  ```

  Change both the `.env` value and the Compose file value together if you rotate the password.
</ParamField>

## Launcher config (`config/loader.config.ts`)

`loader.config.ts` runs before any strategy is loaded. It sets one engine option and waits for MongoDB to become available.

<ParamField body="CC_LAUNCHER_CANDLE_CACHE_DEFAULT" type="boolean" default="false">
  Disables the launcher-level candle cache globally. Set in `loader.config.ts` via:

  ```typescript
  setConfig({
    CC_LAUNCHER_CANDLE_CACHE_DEFAULT: false,
  });
  ```

  Candle caching is also disabled at the per-launcher level in `addLauncherSchema` (`cache: false`). The Yahoo Finance adapter bridges daily bars to minute candles synthetically using `getCandlesSampled`, and `PersistCandleAdapter.useDummy()` is called in the exchange module to keep those synthesized candles out of MongoDB entirely. Disabling the cache at both levels ensures that no synthetic minute data is persisted or reused across runs.
</ParamField>

<Warning>
  Do **not** edit the generated month folders (e.g. `content/oct_2020/`, `content/nov_2020/`, …) directly. All months except `content/sep_2020/` are produced by the generator script and will be overwritten the next time it runs. To change the strategy logic or any constant, edit the reference month at `content/sep_2020/main.strategy.ts` and then regenerate all months:

  ```bash
  node scripts/common/generate_months.mjs --source content/sep_2020
  ```
</Warning>
