The `content/multi_asset/` folder is a self-contained strategy that applies the same BTC trend gate from the index fund to a broader, traditionally diversified portfolio. Rather than running month by month, it covers a single long frame from 2015 to the present — eleven years processed in minutes thanks to the same daily-bar sampling used by the monthly strategies.

<Note>
  The multi-asset folder is **not** generated by `generate_months.mjs`. It is maintained manually as a standalone strategy and will not be overwritten or modified by the generation pipeline.
</Note>

## The four instruments

One instrument per asset class, all sourced from Yahoo Finance daily bars:

| Symbol | Asset class | Exchange / note |
|---|---|---|
| `BTCUSD` | Crypto | Binance spot, via Yahoo Finance |
| `GC=F` | Commodities | COMEX gold futures |
| `^GSPC` | Equities | S&P 500 index |
| `TLT` | Bonds | iShares 20+ Year Treasury Bond ETF |

## Weighting and the trend gate

Weights are determined by **equal risk contribution** from the 90-day covariance matrix of daily returns — a risk-parity allocation that sizes each leg so that every asset class contributes the same amount of portfolio variance.

The crypto leg (`BTCUSD`) is additionally multiplied by the same BTC trend gate used in the index fund: the fraction of the six lookback windows (20, 25, 30, 35, 40, 45 days) on which Bitcoin closed higher than it did that many days ago. When the gate is below 1, the freed fraction of the crypto allocation is redistributed proportionally to the other three asset classes. When the gate is 0, Bitcoin contributes nothing and the full deposit is distributed among gold, equities, and bonds according to their risk-parity weights.

## Holding period and cycle

Each position is held for one week and exited by time. Re-entry occurs on the next daily tick after the weekly position closes — the same pattern as the monthly index fund strategies.

## Running the backtest

```bash
npm start -- --backtest --entry ./content/multi_asset/main.strategy.ts
```

No runner script is needed: the strategy covers the full frame in a single process. The output report lands at `content/multi_asset/dump/report/backtest.jsonl`.

## Data approach

The multi-asset strategy uses the same data pipeline as the monthly index fund folders:

- `classes/YahooFinance.ts` fetches daily bars from the Yahoo Finance chart API — no API key, no ccxt, one request per ticker covering up to 15 years
- `getCandlesFilled` services `1d` interval requests, repairing weekends, holidays, and anomalous bars (zeros, hundredfold wicks) with a flat bar from neighbouring closes
- `getCandlesSampled` repeats the repaired daily bar across all sub-day intervals, so every minute within a day carries that day's high, low, and close
- `PersistCandleAdapter.useDummy()` keeps synthesized candles out of MongoDB
- `CC_BACKTEST_STEP_MINUTES: 24 * 60` tells the engine to evaluate each position once per daily bar instead of 1 440 times on identical minute candles

**Known approximation:** because the daily bar's high, low, and close are only known at the end of the day, sampled minute candles carry those values from the start of the day. For weekly time exits this has no effect on results — the position is held for a full week and exits at the daily close. It would matter for intraday stop-losses, but the strategy sets its stops at levels unreachable in a week on spot markets.

<Tip>
  The multi-asset variant is a good starting point for adapting this template to traditional asset classes. The folder is self-contained: swapping instruments, adjusting the covariance window, or replacing the BTC gate with a different risk-on/risk-off signal requires editing only `content/multi_asset/main.strategy.ts` and `content/multi_asset/modules/backtest.module.ts`.
</Tip>
