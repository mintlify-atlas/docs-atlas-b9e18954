`verify_yahoo_tickers.mjs` validates every resolved Yahoo Finance ticker against actual Binance price data. For each coin in each basket month it fetches Yahoo daily bars and compares the closes at the start and end of that month against the Binance monthly close. Tickers that mismatch systematically are set to `null`; isolated bad months are recorded so that `build_universe.mjs` can exclude only those specific months from baskets.

## Usage

```bash
node scripts/common/verify_yahoo_tickers.mjs [--only SYM1,SYM2]
```

## Flags

<ParamField path="--only" type="string">
  Comma-separated list of Binance symbols to verify, for example `BTCUSDT,ETHUSDT`. All other entries in `yahoo_tickers.json` are left untouched. Useful for re-checking a single coin after manually editing its ticker without re-running the full verification pass.
</ParamField>

## Decision Rules

Each basket month for a coin is tested at two price points — the **start** edge (close of the prior month) and the **end** edge (close of the month itself) — so that any chunk of foreign price history grafted onto the series is visible from the start edge even when the end edge looks correct.

| Condition | Classification |
|---|---|
| `\|log(yahoo / binance)\| > 0.15` (15% log-scale) | Bad month |
| `binance_price < 1e-5` USD | Bad month — Yahoo's 7-digit precision gives price steps larger than 1% below this threshold |
| Yahoo has no bar within 4 days of the month edge | Bad month (gap) — the series is broken at the check point |
| Bad months > 50% of all basket months | Entire ticker set to `null` (systematic mismatch) |
| Bad months ≤ 50% of basket months | Ticker kept; bad months written to `badMonths` array and excluded from baskets |

## Outputs

| File | Description |
|---|---|
| `scripts/common/yahoo_tickers.json` | Updated in place: tickers that fail the majority test are overwritten with `null`; passing tickers gain or update a `badMonths` array listing individual excluded months. |
| `scripts/common/yahoo_tickers_rejected.json` | Records each rejected ticker with its symbol, the Yahoo ticker string, and a human-readable reason describing the worst mismatch. |

## Known Rejection Patterns

The following categories of problem are detected by this script and documented in its source comments:

- **Token name collisions** — a Yahoo ticker refers to a different crypto project that happened to list under the same base symbol (examples: `APE-USD`, `ARB-USD`, `TON-USD` all have name-collision history).
- **Price denominations** — a token was redenominated without a ticker change, creating a step in the price series (example: `NPXS` underwent a 1000:1 consolidation in 2021).
- **Chunks of foreign history** — a Yahoo series contains bars from a different asset before a certain date, making that date range unusable (example: `OP-USD` before October 2022 carries unrelated price history).
- **Migration gaps** — the series is missing bars around a token migration event, leaving a hole that the backtest engine cannot fill (example: `DYDX` in November 2023).

## After Verification

Once this script finishes, the universe and all month folders need to be rebuilt to reflect any newly nulled tickers or updated `badMonths` entries:

```bash
node scripts/common/build_universe.mjs
node scripts/common/resolve_yahoo_tickers.mjs   # if new coins now need resolution
node scripts/common/build_universe.mjs           # repeat until exit code 0
node scripts/common/generate_months.mjs
```

<Warning>
  If verification rejects a ticker that was already used in generated month folders, those months are now based on a bad data source. Every affected `content/<month>/` folder must be regenerated by re-running `generate_months.mjs`, and the backtest for those months must be re-run from scratch to produce valid reports.
</Warning>
