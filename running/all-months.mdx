The repository covers 73 calendar months from September 2020 through September 2026. Running them one by one by hand is impractical, so `generate_months.mjs` produces a pair of runner scripts — one for Linux/macOS and one for Windows — that replay every month in chronological order with a single command. Each month is an independent CLI process; the scripts do not share state between them.

<Warning>
  Both Docker services — Mongo and Redis — must stay running for the **entire duration** of the full replay. If either service goes down mid-run the current month's process will hang and no further months will start. Bring the services back up and re-run from the interrupted month.
</Warning>

## Running All Months

The runner scripts are regenerated by `generate_months.mjs` whenever the basket data or month list changes. Run them from the repository root:

```bash
# Linux/macOS
bash scripts/linux/generate_strategy.sh
```

```bat
# Windows
scripts\win\generate_strategy.bat
```

Both scripts invoke the CLI directly via `node ./node_modules/@backtest-kit/cli/build/index.mjs` rather than through `npm start`, which avoids npm's process-wrapper overhead across 73 consecutive launches.

## How the Scripts Work

Each line in the generated script runs one month in `--backtest` mode without `--ui`:

```bash
node ./node_modules/@backtest-kit/cli/build/index.mjs --backtest --entry ./content/sep_2020/main.strategy.ts
node ./node_modules/@backtest-kit/cli/build/index.mjs --backtest --entry ./content/oct_2020/main.strategy.ts
# ... one line per month, chronological order through sep_2026
```

The months are listed in chronological order from `sep_2020` to the most recent month on disk. Because each month calls `kill()` via SIGKILL when all its symbols finish, every process exits with code 137. The shell scripts do not treat this as an error — execution continues to the next line unconditionally.

## Runtime Estimate

Each month processes approximately 30 daily steps across 21 symbols (20 basket coins plus PAXGUSDT). Yahoo Finance candles are fetched once per ticker at the start of each month's run; subsequent steps for the same ticker are served from the in-memory cache. Expect each month to take on the order of one to several minutes depending on network latency to Yahoo and machine speed. A full 73-month replay typically runs in under two hours on a fast machine with a stable internet connection.

## Viewing the Aggregate Summary

Once all months have run, generate the cross-month summary table with:

```bash
node scripts/common/summarize_reports.mjs
```

This folds every `content/<month>/dump/report/backtest.jsonl` (or `assets/backtest.jsonl` if the report has been copied there) into a single table, grouped by month and year, with a cumulative TOTAL row. See [Reading Reports](/running/reading-reports) for a detailed explanation of every column.

## Detecting and Recovering from Incomplete Months

The summary output includes an `opened` and a `closed` count for each month. A healthy month has equal counts — every position that was opened was also closed. Two failure modes produce mismatches:

| Symptom | Cause | Fix |
|---|---|---|
| `opened != closed` in the summary | The process was interrupted before all positions closed | Re-run that month individually |
| `(no report)` in the summary | The process crashed before writing any output | Re-run that month individually |

Re-run a single failed month with the standard single-month command:

```bash
npm start -- --backtest --entry ./content/jan_2022/main.strategy.ts
```

<Note>
  Reports are **not cleared between runs**. Re-running a month **overwrites** the existing `content/<month>/dump/report/backtest.jsonl` file rather than appending to it. If you need to preserve a previous result, copy it elsewhere before re-running. The `assets/backtest.jsonl` files checked in to the repository are static snapshots and are not touched by the runner.
</Note>

After recovering any interrupted months, re-run `node scripts/common/summarize_reports.mjs` to regenerate the aggregate summary with the corrected data.
